# review-pr-compare

## 目的と終わりの状態

review-pr-topdown（以下 topdown）を主にして他者の PR をレビューし、review-pr-steps（以下 steps）の結果と突き合わせて、漏れを投稿の前に補う。あわせて、steps だけが拾ったものを記録し、topdown を直す材料と、steps を退かせる判断の材料を PR をまたいで貯める。目的は topdown の精度を上げて steps を退かせることで、比較の数を貯めること自体ではない。

終わったと言えるのは、topdown の終わりの状態（判断と根拠、確かめられなかった範囲、コメントの配置先・文面・レビューの種類への合意）に達して投稿し、比較の記録を書いたとき。

投稿済みのレビューへの返信や追加のコミットへの対応には使わない。返信への応じ方の手順は、2 つの方式で同じファイルなので、比べても差が出ないため。

## 進め方

1. 始めるときに、このスキルが頼むサブエージェント（steps を走らせる開発担当、比較を判定する開発担当）と、topdown が頼むサブエージェントを示し、承認を求める。
2. steps の事前確認を、背景の開発担当のサブエージェントに走らせる。渡すのは、PR、判断する head の SHA、steps の SKILL.md と手順書の場所（`~/.claude/skills/review-pr-steps/`）、書き出し先だけで、topdown の判断は渡さない。手順書の 1 周目（事前確認、Step 1〜5）だけを行い、PR への書き込みはせず、指摘の一覧を書き出させる（指摘ごとに、要旨・箇所・害・根拠・確かさ・推奨する対応。解消した候補と確かめられなかった範囲も）。コードは固定した SHA の git のオブジェクトで読ませる。レビューの間に PR が更新されうるため。
3. topdown の SKILL.md（`~/.claude/skills/review-pr-topdown/SKILL.md`）を読み、それに従って見取り図と判断を示す。steps の一覧は、topdown の判断をすべて示し終えるまで読まない。先に読むと、topdown が何を拾うかを測れなくなるため。コメントの文面と投稿は、4 と 5 の後に行う。
4. topdown の判断をすべて示し終えたら、topdown の指摘と、ユーザーとの議論で出た指摘を、steps と同じ形で書き出し、比較の判定を、会話の文脈を持たない開発担当のサブエージェントに頼む。指摘ごとの出どころ（topdown か、ユーザーの問いか）は判定役に渡さず、対応の控えに書く。2 つの一覧はどちらの方式かを伏せて X・Y とし、判断した head の SHA を渡す。判定させるのは、同じ問題を指す指摘の対応、片方だけの指摘が現物で成り立つか、逆の判断の 3 つ。メインの側で判定しないのは、自分が拾えなかった指摘を割り引いて見るおそれがあるため。
5. steps だけが挙げて成り立つと判定された指摘を、topdown の指摘と同じ形（害・根拠・対応の案と推奨）でユーザーに示し、レビューに加えるかを合意する。投稿の前に置くのは、取りこぼしをユーザーの名義で外に出す前に埋めるため。その後、topdown の「文面と投稿」に進む。
6. 比較の記録を書く。判定の結果に、ユーザーに尋ねた示し方の印象（分かりやすさ・負荷）を添え、まとめの記録に 1 行足す。漏れを観測した観点は所見として書き、スキルを直すかはユーザーが決める。

## 数え方

steps を退かせる判断に使うのは、steps だけが拾って成り立ち、ユーザーがレビューに加えた指摘の数。成り立っても、ユーザーが加えなかった指摘（害が小さい、この PR で扱うべきでないなど）は数えない。ユーザーとの議論で出た指摘は topdown の側に数える。退かせる判断は topdown とユーザーの協働で洗い出せているかで行うため。topdown だけが落とした指摘（steps だけのものと、ユーザーの問いから出たもの）は、topdown を直す材料として所見に書く。

## 記録の場所

組織のリポジトリの中身を含むので、公開の dotfiles には置かない。

- PR ごと: `~/tmp/review-compare/<リポジトリのディレクトリ名>-pr-<番号>/`。steps.md・topdown.md・対応と出どころ（mapping.txt）・判定（comparison.md）を置く
- 伏せた写し: `~/tmp/review-blind/<同じ名前>/` に X.md・Y.md を置き、判定役にはここと PR の現物だけを読ませる。元の一覧の隣に置かないのは、判定役が元の一覧を読めないようにするため
- まとめ: `~/tmp/review-compare/log.md` に、PR ごとに 1 行（日付、PR、両方・topdown の側だけ・steps だけの成り立つ指摘の数、steps だけのうちレビューに加えた数、ユーザーの問いから出た指摘の数、示し方の印象、所見）

## 約束

- steps のサブエージェントと判定役には、読み取りだけをさせる（編集・コミット・PR への書き込みをしない）
- topdown の約束（PR に書き込む操作はユーザーの承認の後で、直前に head を確かめる。他者向けの文面の手順。Comment と Approve の選び方）はそのまま守る
