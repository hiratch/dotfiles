# 引き継ぎの記録

dotfiles 以外のセッションが、合意した候補を dotfiles のセッションに渡すための形。dotfiles のセッションは、これを読み、その時点の指示のファイルに照らして反映し、反映の後に消す。引用には組織の内容が含まれるので、dotfiles に写すのは「案」の欄だけ。

## 場所と名前

`~/tmp/session-review/<作業ディレクトリ名>-<日付>-<セッション ID の先頭 8 文字>.md`。同じセッションで振り返りを重ねたら同じファイルに追記する。

## 形

```markdown
# セッションの振り返りの引き継ぎ

- 作成: <日付>。作業ディレクトリ <名前>。担当 <なし・開発・研究>。セッション ID <ID>。記録 <JSONL のパス>
- 扱い: dotfiles のセッションが読み、その時点のファイルに照らして反映し、反映の後にこのファイルを消す。「案」以外の欄は dotfiles に写さない
- 読み込まれていた指示: <照合に使ったファイルの一覧>

## 候補（ユーザーが採る、または直して採ると応えたもの）

### C1 <一言>
- 事象: <記録の引用。発言者、行番号か時刻>
- 求めていたこと: <ユーザーの訂正・問いの引用。無ければ「ユーザーの反応なし。こちらの見立て」>
- 機構: <SKILL.md の表のどれか。根拠の種類（引用・読解・推測）>
- 既存の規則との照合: <当てはまる規則の引用とファイル・節。無ければ探した場所>
- 案: 置き場 <ファイル・節>。文面 <目的と動機の形。組織固有の語を含めない>。削るもの <あれば>
- 確かめ方: <次にどの場面で何を観察すれば効いたと言えるか>
- ユーザーの判断: <採る／直して採る（直した点）>
- 題材（任意）: <再現に要る最小の入力と状態。設定を変えるたびに流すための材料。形式は未合意>

## 候補にしなかった事象（1 行ずつ）
- <何が起き、なぜ候補にしなかったか（一回限り、案件固有、指示では変わらない、など）>

## 働いたもの（規則・約束を残す根拠）
- <どの規則・約束・hook が、どの場面で何を防いだか>

## 接し方の所見（dotfiles には反映しない。ユーザーが読むためのもの）
- 効いた入力: <どの言葉が何を変えたか>
- 足りなかった情報が後から出た箇所: <その情報が先にあれば何が変わったか。ユーザーがその時点で知り得たか>
- 根拠が薄かったか後の情報と整合しなかった判断: <その時点の情報で何ができたか。今の情報で何を変えるか>
```

## dotfiles のセッションでの扱い

候補は提案であり、分類も文面も、dotfiles のセッションがその時点のファイルで確かめ直す（振り返りの後にファイルが変わっていることがある）。反映は CLAUDE.md の協働スタイル節の作法に従い、書き込む内容そのものをユーザーに示してから行う。「題材」があれば、設定の変更の観察点として案件のメモリに残すかをユーザーに諮る。
