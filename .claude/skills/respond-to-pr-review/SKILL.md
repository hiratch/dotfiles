name: respond-to-pr-review
description: 自分が作成した PR にレビューコメントや返信が付いたときの対応手順。コメントの原文と日本語訳、指摘内容の解説、方針の選択肢の提示を経てユーザーの判断を得てから修正し、返信の投稿と re-review 依頼までを行う。「レビューコメントが付いた」「レビューに返信が来た」と言われたときに使う（他者の PR をレビューする review-pr、ready 前の self-review-pr とは別）。
---

## 目的
レビュー指摘への対応をユーザーの判断で進める。修正案を先に出さず、ユーザーが指摘を理解して方針を選べる状態を先に作る。

## 進め方
1. 取得: `gh api repos/{owner}/{repo}/pulls/{n}/comments`（inline・対象行・diff_hunk・in_reply_to）、`.../reviews`（状態と本文）、`gh pr view --json comments`。
2. 提示（修正案より先に、この順で 1 メッセージに）:
   - コメントの原文と日本語訳（対象ファイル・行・該当コードの要約を添える）
   - 指摘内容の解説。ユーザーが文脈を覚えていない前提で、どこで・何が・どの条件で起きるか・深刻度を書く。真偽は可能なら実行で確かめ、読解と実測を区別して書く
   - 方針の選択肢と推奨。ここで止まり、ユーザーの判断を待つ
3. 判断後: 修正 → formatter/linter → 対象テスト → 挙動不変を主張する PR なら全 suite を `--force-regen` で回し差分を確認 → コミット・push。
4. 返信案を日本語で起こして校正を受け、英訳して投稿する（`gh api ... /comments/{id}/replies`）。指摘に同意して直した場合は、何を直したかとコミットを示す。承認だけの返信は一語で止める。
5. 修正コミットがあれば `~/.claude/hooks/pr-workflow-guard record --branch <branch>` を書き直し、re-review を依頼する。
6. 記録: 指摘と対応をプロジェクトメモリの該当 PR の項に 1 行残す。
