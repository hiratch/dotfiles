---
name: self-review-pr
description: 自分が作成した PR をセルフレビューし、懸念点と判断に迷う点を洗い出したうえで、合意した対応（コード修正または Issue 化）まで実施する。自分の PR を出す前後に品質を点検するときに使う。
---

## 目的
reviewer が問うのと同じ、必要性・方針・実現方法の妥当性を、reviewer に渡す前に自分たちで確かめ、答えられない点を解消する（直す、Description で説明する、Issue にする）。

完了: 合意した対応を終え、self-review の記録を書いた時点。

## 進め方
自身の作ったPRをセルフレビューしたいです。Step 1 から Step 5 は `references/pr-review-steps.md` の共通手順に従い、そのうえで Step 6 として以下を行ってください。

議論の各ステップで
- 修正が必要だと感じる懸念があった場合はその提示をしてください
- 判断に迷う点については、判断に迷う理由も含めて提示してください

あくまでself reviewですので、懸念に当たらないのであれば提示は不要です。ただし事前確認で解消した懸念は、手順書のとおり解説の中で述べてください。
その上で私が内容について掘り下げたいことがあれば質問することがあります。

各 Step で修正が必要だと合意した指摘は、Step 6 に回さず、その Step のうちに直してコミットする。
- 直した結果、それより前の Step で確かめたことが崩れていないかを確かめ直す（例: Description を直したら、Step 1 の Description と diff の突き合わせをやり直す）
- 直し方が後の Step の論点に左右される場合は、その論点を前倒しで判断してから直す（例: README の手順が Step 3 の設計の判断で変わる場合）
- 別 PR で扱うべきもの（Issue にするもの）は、合意した時点で Issue の文面を下書きする

## Step 6: 総括
Step 6 は議論の最後に行う。修正は各 Step で済んでいるので、ここでは次を行う。
- 各 Step の指摘と、直したか・直さずに閉じたか（その理由）の一覧
- 事前確認で確かめられなかった範囲と、議論で詳しく扱わなかった範囲を明示する
- Issue にすると合意したものを起票する
- 最終の状態でテストの全体を流し、結果を確かめる
- self-review の記録を書く: `~/.claude/hooks/pr-workflow-guard record --branch <レビューしたブランチ>`。記録するのはコミット済みの変更内容なので、すべてコミットしてから記録する。reviewer 指定・ready 化の前に、このガードが記録と照合する
